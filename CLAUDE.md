# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

alfresco is a Spotlight-style URL and app launcher for macOS with a 24-hour clipboard history on a second hotkey, a pomodoro timer and system commands (`/zz` to sleep, `/lockscreen`, `/displaysleep`) driven from the launcher, an upcoming-events list (`/cal`) read from macOS Calendar, a subway departure board (`/transit`) from the MTA's real-time feeds through the transit service, a pomodoro view under `/pomo`, a usage report under `/stats`, named pinned clips pasted with `/snip <name>`, and built-in answers (calculator, unit and time zone conversion, UUID, timestamp, dates) copied from the launcher. It's a few Swift files under `Sources/` compiled together with `swiftc` (AppKit + Carbon, no Xcode project, no package manager, no dependencies). The keyword → URL mappings live in `workflows.json`, which is data, not code, and is committed to the repo; keywords are typed after `/` (`Config.commandPrefix`).

## Build & run

Needs the Xcode 16+ Command Line Tools only (Swift 6 compiler, for `-swift-version 6`).

```bash
# Plain binary (finds workflows.json next to itself)
swiftc -O -parse-as-library -swift-version 6 -target "$(uname -m)-apple-macos12.0" $(find Sources -name '*.swift') -o Launcher && ./Launcher

# .app bundle -> build/Launcher.app (LSUIElement; icon from Resources/AppIcon.png via sips +
# iconutil; signed with the "alfresco Local Signing" certificate when the keychain has it,
# else ad-hoc; SIGN_IDENTITY overrides)
./build.sh

# Build, quit the running copy, replace ~/Applications/Launcher.app and start it
./install.sh

# Point a running binary at a specific workflows file
ALFRESCO_WORKFLOWS=/path/to/workflows.json ./Launcher

# Check a workflows file with the app's decoder and exit (no file: the one the app reads)
./Launcher --check workflows.json
```

`-parse-as-library` is required because `Sources/App/Launcher.swift` uses `@main`. `-swift-version 6` turns on Swift 6 language mode, so data-race safety violations are compile errors rather than warnings; keep it on every build command. `-target …-apple-macos12.0` sets the minimum macOS version to match `LSMinimumSystemVersion` in `build.sh`; without it the binary only runs on the macOS it was built on or newer, and `#available` fallbacks never run. Keep it on every build command too, including `Tests/run-self-tests.sh`. Every `.swift` file under `Sources/` (any depth) is compiled in as one module, so new source files are picked up automatically and folders have no effect on visibility. There is no linter or formatter. The checks are "compiles with `swiftc`", `./Launcher --check workflows.json` and the runtime self-test (below), all run by CI (`.github/workflows/build.yml`, on a macOS runner). `Resources/AppIcon.svg` is the icon's source and `Resources/AppIcon.png` (1024 px, transparent corners, artwork inside Apple's 824 px grid) is what the build uses; re-export the PNG whenever the SVG changes. `build/` is gitignored, but a plain `Launcher` binary built in the repo root is not, so don't commit it. Signing matters: TCC keeps the Accessibility and Calendar permissions per signature, and an ad-hoc one changes every build, so `build.sh` uses a local self-signed certificate when there is a valid one (`find-identity -v`, signed by SHA-1 so duplicates or an expired copy never break the build; README.md, "Signing"); CI has none and signs ad-hoc.

## Self-test

```bash
# Builds the self-test variant and runs it as a plain binary, inside an .app,
# across a relaunch, and held in the menu bar for a screenshot.
Tests/run-self-tests.sh   # log and screenshot in build/self-test/

# Also runs the perf suite (timings only, not in CI); numbers in build/self-test/perf.log.
PERF=1 Tests/run-self-tests.sh
```

`Tests/SelfTest/` is compiled in only with `-D SELFTEST` (with `Sources/`), so release builds contain none of it. `Launcher --self-test <suite>` (`unit`, `perf`, `relaunch-write`, `relaunch-read`, `menubar-hold`) skips the single-instance lock and hotkeys, runs the suite inside a real `NSApplication`, prints a `PASS` / `FAIL` line per `check(name, condition)` and exits 0 only if all passed. It requires `ALFRESCO_SUPPORT_DIR` (honored by `ClipboardStore.directory` only in that build), so it never touches the real support folder; in that build `Config.weatherAPIKey()` and `Config.transitService()` are always nil (no `ALFRESCO_WEATHERAPI_KEY`, `ALFRESCO_TRANSIT_*` or `~/.config/alfresco` file is read), so a launcher the test drives never fetches with the real key or token. Time-dependent code takes an injected clock (`BuiltInContext`, which also pins the time zone, locale and UUIDs for the built-ins, `PomodoroTimer(fileURL:now:wakeNotifications:calendar:)`, which also takes its own wake notification center and the calendar that says which day a session ended on, and `UsageStats.makeForSelfTest(fileURL:now:calendar:)` and `TypedAppPicks.makeForSelfTest(fileURL:now:calendar:)`, since their own inits are private), and alerts go through a `PomodoroAlertSink` the test replaces with a recorder. Accessors that exist only for the test (`PomodoroStatusItem.isShown`, `menuTitles`…, `UsageStats.dayKeys`) are inside `#if SELFTEST`, so release builds keep those members private. The test bundle is built from the same binary with `EXECUTABLE=` and its own `BUNDLE_ID` (`local.launcher.selftest`), so it never registers as the real app. CI writes the PASS/FAIL list to the run summary and uploads the log, a menu bar screenshot, and renders of launcher screens: with `SELFTEST_RENDER_DIR` set (the plain binary's unit run), `FloatingPanelController.renderForSelfTest(appearance:)` draws the panel off screen in light and dark mode, on a flat background since the frosted one samples what is behind the window (`TransitTests` writes `transit-setup-*.png` and `transit-board-*.png`). `perf` (`Tests/SelfTest/PerfTests.swift`, macOS 13+, run only with `PERF=1 Tests/run-self-tests.sh`, never in CI) seeds a 500-item history through `ClipboardStore.add`/`saveNow` and `ClipImageFile.save`, drives the real `ClipboardController` and `LauncherController` through `#if SELFTEST` accessors (`typeForSelfTest`, `selectForSelfTest`, `writeForSelfTest`, which writes to a private named pasteboard, `AppIndex.matchCallsForSelfTest`…), and prints the median and p95 per scenario with `ContinuousClock`; its only checks are on its setup, never on a number. `PERF_RUNS`, `PERF_ONLY` (one scenario, with a pause after `PERF_READY` so `sample` can attach) and `PERF_BIG_TEXTS` tune it. When a change has behavior the self-test can reach, add checks next to the existing ones; in the PR description, add a "Verification" section that links the CI run and lists what was checked by hand (sound, notification banners and real sleep can't be checked on the runner).

## Architecture

Source layout: `Sources/<Feature>/`, one folder per feature. `App/` holds the wiring (`AppDelegate`, `main`, `Config`), `Shared/` holds code used by more than one feature (e.g. `DigitShortcuts`, the ⌘1 to ⌘9 key codes both panels use; `StatusRow`, the weather and calendar loading / error line; `NSTextField.areaLabel`, the calendar and pomodoro areas' label style; `KeywordInput`, `<keyword> [argument]` parsing, bare for the built-ins and with `init(command:)` after the `/` for weather and calendar; `DateReading`, the first part of `DateMath` (`parseDate`, `namedDay`, `days(from:to:calendar:)`, `isoCalendar`) and `BuiltInContext`, used by the built-ins and the calendar; and `SetAsideFile`, which moves an unreadable data file to `<name>.unreadable.json`, `-2`, `-3`… up to 100, never replacing an earlier one; when it returns nil the caller sets `canSave` false and doesn't save that run). Each folder has a user-facing `README.md` (what the feature does, its `Config` settings, its files); the root `README.md` is an overview that links to them, plus build and login-item setup.

### App/Config.swift

The `Config` enum holds compile-time settings: both hotkeys (`hotKey`, `clipboardHotKey`), `showMenuBarIcon`, app launching (`appSearch`, `appFolders`, `appRescanInterval`), `settingsPaneSearch`, the built-ins' prefix and keywords (`calculatorPrefix`, `timeKeyword`, `uuidKeyword`, `timestampKeyword`, `daysKeyword`, `weekKeyword`; nil turns one off), the clipboard limits (`clipboardRetention`, `clipboardMaxItems`, `clipboardMaxPinnedItems`, `clipboardMaxPinnedImages`, `clipboardMaxTextBytes`, `clipboardMaxImageBytes`, `clipboardMaxImagePixels`, `clipboardPollInterval`) and `clipboardIgnoredApps` (bundle IDs whose copies are never recorded), the weather settings, the transit settings (`transitKeyword`, `transitStation`, `transitNorthLabel`, `transitSouthLabel`, `transitDepartures`, `transitCacheLifetime`, and `transitService()`, the service's address and token: `ALFRESCO_TRANSIT_URL` / `ALFRESCO_TRANSIT_TOKEN`, else `~/.config/alfresco/transit-url` / `transit-token`, read through `userSetting(environment:file:)` like `weatherAPIKey()`, nil in the `SELFTEST` build), the calendar settings (`calendarKeyword`, `calendarDays`, `calendarSearchDays`, `calendarMaxEvents`, `calendarAccounts`, `calendarExcluded`, `calendarHidesBirthdays`, `calendarHidesDeclined`, `calendarCacheLifetime`, `calendarStrip`), the pomodoro settings (`pomodoroFocus`, `pomodoroShortBreak`, `pomodoroLongBreak`, `pomodoroSessionsBeforeLongBreak`, `pomodoroAutoStartBreaks`, `pomodoroSound`), the usage stats switches (`usageTracking`, `usageTrackFallbackWords`, `usageRetentionDays`, and `usageReportDays`, the days `/stats` adds up), the learned app picks (`learnTypedAppPicks`, `typedAppPicksRetentionDays`, `typedAppPicksMaxInputs`), `workflowURLSchemes` (the only schemes a workflow `url` may use, so workflows.json alone can never open a `file:` URL), `commandPrefix` (`/`, typed before every keyword; nil types them bare) and `commandListKeyword` (`help`), `workflowCardLimit` (the command cards under the empty input; nil turns them off), and `workflowsSource`, which resolves the workflows file in this order: `ALFRESCO_WORKFLOWS` env var → `AlfrescoWorkflowsFile` Info.plist key (written by `build.sh` as the repo's absolute path, so moving the repo requires a rebuild) → `workflows.json` next to the executable → `~/.config/alfresco/workflows.json` (the only location auto-created if missing).

### Launcher/Workflows.swift

- **Workflows** — `Workflow` / `WorkflowSet` are `Decodable` models of `workflows.json`; `ArgumentTransform` parses string transforms like `"stripPrefix:#"`. `WorkflowStore` re-reads the file only when its modification date changes (checked each time the launcher opens) and keeps the last good `WorkflowSet` when a reload fails, exposing `loadError` for the UI.
- **Command prefix** — `CommandInput` (in `Workflows.swift`, not `Shared/`, though several features use it: `check.sh` compiles `Workflows.swift` on its own) is the one place that reads `Config.commandPrefix`: `isCommand` (input starts with it), `body(of:)` (input without it, nil for bare input and for a space right after the prefix, so `/ zz` runs nothing), `typed` (adds it, for display and completions) and `stored` (drops a leading one from a keyword in the file, so keywords are always stored bare, as are `Command.source` and the usage stats keys). Bare input never reaches a workflow; command input never reaches apps, built-ins or the fallback (`isUnmatched` is false, `parse` is nil for an unknown one and `execute` beeps, after `UsageStats.recordUnknownCommand` keeps its first word under the fallback-word rule), except that ⌘↩ runs `CommandParser.fallbackCommand` on it. `WorkflowSet.listsAllCommands` (the prefix alone, or `/help` while no workflow has `help`) makes `suggestions(for:)` return every workflow. With a nil prefix everything behaves as before the prefix existed.
- **Command parsing** — `CommandParser.parse` splits input after the prefix into `<keyword> [argument]`. A workflow whose `url` contains `{query}` requires an argument; one without `{query}` matches only the bare keyword. `WorkflowSet.workflow(for:withArgument:)` picks the first workflow of the right form, so one keyword can have both (e.g. `/weather` and `/weather paris`). Input without the prefix goes to `fallback`. `Command.source` says which (`.workflow(keyword:withArgument:)` with the workflow's first keyword, or `.fallback`), for the usage stats. Arguments are percent-encoded with the RFC 3986 unreserved set. An optional `preview` URL template is expanded the same way into `Command.preview`. `Workflow.init(from:)` sets `refusal` for a `url` whose scheme (`Workflow.scheme(of:)`, nil when `{query}` comes before the `:`) isn't in `Config.workflowURLSchemes`, and `previewRefusal` (with `preview` nil) for a preview that isn't https (or `{service}/…`) or uses `{query}` when `url` doesn't. `WorkflowSet` leaves refused workflows out and keeps those with only a refused preview, lists both in `refused`, which `WorkflowStore` reports as `loadError` while using the rest of the file. A refused `fallback` fails closed: `WorkflowSet.fallback` is nil (it is the built-in Google search only when the file has none), `CommandParser.parse` returns nil for unmatched input, and `LauncherController.execute` beeps; `CommandParser.isUnmatched` still lets apps take that input. `WorkflowSet.keywords` is every usable keyword.
- **Checking** — `WorkflowCheck` (`WorkflowCheck.swift`, Foundation only) is `Launcher --check [file ...]`, handled in `LauncherApp.main` before the single-instance lock (no file: `Config.workflowsSource`, never created; a missing `~/.config` fallback is OK, since the app writes the defaults there). It decodes with `WorkflowSet` and reports `WorkflowStore.describe`'s message or each `refused` entry as an error, and a keyword shadowed by an earlier workflow of the same form (`shadowedKeywords`) as a warning; exit 1 on any error. `.claude/skills/add-workflow/scripts/check.sh` compiles it with `Workflows.swift` for the same verdict, so it must not depend on anything else.

### Launcher/AppIndex.swift

`AppIndex` (main actor) lists the `.app` bundles in `Config.appFolders`, each directly and one folder down, scanned in a detached task at launch and again when the launcher opens if older than `Config.appRescanInterval`. Each `AppEntry` matches on its folded (case/accent-insensitive) Finder display name and file name. `results(for:limit:openCounts:picks:)` (which wraps `rankedResults(_:panes:for:limit:openCounts:picks:)`, nonisolated and pure, which the self-test checks, as does `ranked(_:for:limit:openCounts:picks:)`, its apps only; after `normalize`: trim and fold, also `TypedAppPicks`'s key) ranks exact name, name prefix, word prefix (several typed words must start consecutive words), then initials; `openCounts` (bundle ID → opens, from `UsageStats.totals()`) lifts an app by `log2(1 + opens) / 5` tiers, at most 2, so a much-used app can beat a closer name; `picks` (bundle ID → weight, `TypedAppPicks.picks(for:)` of the exact input) puts the apps picked for that input before every tier but the exact name, heaviest first. An exact name always comes first; ties go to the shorter name, then alphabetical. `AppEntry.bundleID` is read at scan time for this. Apps only take input that would otherwise go to the fallback (`Command.isFallback`), never `/` input.

The same index holds the System Settings panes (`SettingsPanes.swift`, `Config.settingsPaneSearch`): `SettingsPanes.all` is a table of `SettingsPane` (extension bundle ID, English and French names, aliases; `url` is `x-apple.systempreferences:<id>`, `title` French when the first preferred language is), filtered once, at the first scan, by `installed()` to the IDs of the `.appex` bundles in `/System/Library/ExtensionKit/Extensions` (none before macOS 13), since Apple renames panes between versions. `results(for:limit:openCounts:picks:)` ranks apps and panes together as `LauncherItem`s through `rankedResults`: same tiers, no usage lift and no picks for panes (an exact pane name still beats a picked app), an app before a pane of the same score. `LauncherController.matchedResult()` is the row Enter takes without a highlight; a pane opens with `NSWorkspace.open` (beep on failure) and records `launcher.openedSettingsPane`, never which pane. `SettingsPaneTests` checks the table against the runner's macOS, so a pane renamed in a new macOS fails CI by name.

### Launcher/TypedAppPicks.swift

`TypedAppPicks.shared` (main actor) is Alfred's "learn which result goes with what you type": `LauncherController.open(_:)` calls `record(input:bundleID:)` with the field's text, and `LauncherController.appMatches(for:limit:)` (the one place Enter's `matchedResult` and the list rank apps and panes) passes `picks(for:)` to `AppIndex`, read live (it only changes when an app opens, which closes the panel); `prepareToShow` touches `shared` so the file is read while the panel opens. `picks(for:)` ignores an input last typed before the retention cutoff even before `prune` drops it. Inputs are keyed by `key(for:)` (`AppIndex.normalize`, nil when empty or past `maxInputLength`, 40), only exact keys count. Each key holds bundle ID → weight: a pick adds 1 (at most `maxWeight`, 8) and halves the others (dropped under `minWeight`, 0.25), so a new habit leads after a pick or two and one stray pick doesn't undo an old one; plus the local day it was last typed. It stores what was typed, so it has its own switch (`Config.learnTypedAppPicks`, independent of `usageTracking`) and its own file, `typed-picks.json` in `ClipboardStore.directory`, through `StoreFile` like usage.json. `prune` drops inputs older than `typedAppPicksRetentionDays` calendar days, then the least recently typed past `typedAppPicksMaxInputs`, never the one just recorded. The menu bar's "Forget Learned App Picks" (`forgetAll`, which writes at once; disabled while empty) clears it. Its own init is private; the self-test uses `makeForSelfTest(fileURL:now:calendar:)` (`Tests/SelfTest/TypedAppPicksTests.swift`).

### Launcher/PreviewFetcher.swift

`PreviewFetcher` (main actor) fetches `Command.preview` for the launcher hint: debounced 400 ms, one request in flight (a new URL cancels the old one, and so does input that no longer has a preview or hiding the panel), 5 s timeout, reads at most the first 1 KB (`bytes(for:)`, then the task is cancelled), keeps the first non-empty line of a 2xx non-HTML answer for the response's `max-age` (`PreviewRequest.lifetime`: 5 s to 10 minutes, 10 minutes without one; never `s-maxage`, the CDN's). Failures are silent. `PreviewRequest.make` (pure, checked in `SecurityTests`) builds what is sent: a `{service}/…` preview (`Workflow.isServicePreview`, which `CommandParser` turns into an `alfresco-service:/…` URL, `Workflow.serviceScheme`, so `Workflows.swift` stays free of the service config for `check.sh`) is resolved against `Config.transitService()`'s address, read at each fetch, and nil without one (no preview); the transit token goes in `TransitService.tokenHeader` only when the URL's origin is the service's (`HTTPSession.sameOrigin`). `LauncherController.updateHint` shows `"<text>  ↩ <label>"` once it's cached.

### Weather/

The forecast area under the launcher input, shown while the input is `/` + `Config.weatherKeyword` alone or followed by a place (read with `KeywordInput`), and only when a WeatherAPI.com key is set (`Config.weatherAPIKey()`: `ALFRESCO_WEATHERAPI_KEY`, else `~/.config/alfresco/weatherapi-key`; nil turns the feature off entirely). Enter is unaffected: it still runs the workflow from `workflows.json`.

- `WeatherAPI.swift`: not main-actor. `WeatherLoader.load` makes one `v1/forecast.json` request (`q` is the typed place, `Config.weatherHomePlace`, or `auto:ip` for the bare keyword; `days` is `Config.weatherDays`, at most 3 on the free plan) and builds a `Forecast` (current conditions, `hours` from the current hour slot onward across days, and `days`). Error bodies' codes map to `WeatherError` (1006 unknown place, 2007 quota, 1002/2006/2008 key), whose `message` is shown in the panel.
- `WeatherProvider.swift`: main actor. Turns input into a `WeatherQuery`, debounces typed places (400 ms), runs one load at a time, caches results per query (`Config.weatherCacheLifetime`, failures 30 s), and calls `onUpdate`.
- `WeatherStripView.swift`: the strip above the input; its content (icon, temperature, description, city, today's high / low) is right-aligned in the panel's top-right corner, and the view hugs it (the next meeting can sit on the left of the same line). Only that content takes clicks: it subclasses `StripView` (`Shared/StripButton.swift`, shared with the meeting), which owns the `StripButton` (hover highlight, clicked on mouse up inside like a command card, never first responder), `onClick`, `clearHover` and the self-test click; a subclass builds its content in `build()` and passes it to `install(_:help:)`, which makes the strip hug it: `onClick` is `LauncherController.showForecast`, which records `launcher.weatherStripClicked` and puts `/` + `weatherKeyword` in the input through `complete(with:)`, replacing what was typed, so the forecast opens for the strip's own place.
- `WeatherView.swift`: the `NSView` (loading, error and forecast states; the forecast is current conditions, a row of `Config.weatherHours` hourly columns, then a compact one-line-per-day row of `Config.weatherDays` days; SF Symbols for WeatherAPI condition codes; the "Powered by WeatherAPI.com" link the free plan requires). Labels are French.

`LauncherController.updateWeather` shows or hides it and resizes the panel with `FloatingPanelController.setHeight`; while it is shown, the one-line hint `preview` is not fetched. It also fills `WeatherStripView`, the line above the input that shows `WeatherProvider.homeQuery()` whenever `Config.weatherStrip` is on and a key is set. `LauncherController.layoutStrips` (called by `updateWeather` and `updateMeetingStrip`) moves the input row down by `stripHeight` (computed: `StripButton.stripHeight` while the weather or the next meeting is shown, else 0) and turns on `stripGap` (the meeting's trailing edge 12 pt before the weather's leading one) only while both are: the input row is positioned by a layout guide (`rowGuide`) whose top moves down by the strip's height. Requests go one at a time, the typed query first, then home.

### Calendar/

The event list under the launcher input while it reads `/` + `Config.calendarKeyword` (`/cal`) alone or followed by text, and only while that input runs a workflow whose first keyword is `calendarKeyword` (`CalendarQuery.make(input:command:)`, from `Command.source`, worked out once per input change into `LauncherController.currentCalendarQuery` and again by the 30 s timer; `withArgument` passes `KeywordInput.argument` to `make(argument:)`, which gives `.day` for a day `DateMath.namedDay` reads (`demain`, a weekday in full, `12/11`, `25.12.2026`; stricter than `parseDate`, since abbreviations like `sam` and dotted numbers like `1.2` are search words) and `.search` with the folded text otherwise, else `.upcoming`), so Enter always does what the list is about: for a `.day`, `CalendarQuery.enterCommand` runs the bare `cal` workflow's URL instead of searching for the word, keeping the typed form's `source` so the usage stats count `cal …`; without `cal` workflows `/cal` is an unknown command and beeps. Events come from EventKit, so Google calendars appear once the account is added in System Settings > Internet Accounts; there is no Google API or network code. Enter still runs the `cal` workflows from `workflows.json` (the bare one for a `.day`).

- `CalendarProvider.swift`: main actor. `state(for:)` returns `.loading(text)` (permission prompt pending, or no fetch finished yet), `.message` or `.loaded(events, hiddenCount:)` (every upcoming event for `.upcoming`, at most `calendarMaxEvents` for `.search` within `calendarSearchDays`, and for `.day` through `dayList` (nonisolated, pure: events touching the day, finished ones dropped first past the limit)). It is only available when the bundle has an identifier and the Info.plist usage description (`NSCalendarsFullAccessUsageDescription` on macOS 14+, `NSCalendarsUsageDescription` before; written by `build.sh`), because TCC kills a process that asks without one; the plain binary shows a message instead. The permission is asked the first time `/cal` is typed, through `askForAccess`, which is `nonisolated` because the completion handler runs on a background queue; the store is recreated afterwards and `onAccessAnswered(granted)` fires. Clicking the prompt closes the non-activating panel, so on a grant the launcher opens again with the input that asked (`accessPromptInput`, cleared in `prepareToShow` so a later session is never replaced; that reopen isn't counted as `launcherOpened`, nor the prompt's close as a close). Events are fetched for `fetchRange(for:today:)` (`.window(start:days:)` from the start of today: `calendarDays` for `.upcoming`, `max(calendarDays, calendarSearchDays)` for `.search`, so a search's events also serve `cal`, and whichever holds a `.day`; a `fetchedWindow` that starts on another day (after midnight) or is narrower than needed shows `.loading`; a day before today or past both windows is `.day(date)`, fetched alone into `dayEvents` with its own freshness, 400 ms after typing pauses on it (`fetchDay`), so partial dates aren't read; `fetchRangeForSelfTest` exposes the choice under `#if SELFTEST`) in a detached task (`fetch`, `exclusion(of:)` and `makeEvent` are `nonisolated`; the store crosses in `EventStoreBox`, `@unchecked Sendable`, one fetch at a time), copied into `CalendarEvent` (`Sendable`: the calendar color as sRGB `CalendarColor`), delivered through `onUpdate`, and kept for `Config.calendarCacheLifetime`. `EKEventStoreChanged` marks them stale (a `generation` counter, so a fetch already running doesn't count as fresh) and calls `onUpdate`; stale events stay on screen until the next fetch replaces them. Declined events, the Birthdays calendar, `calendarExcluded` names and accounts outside `calendarAccounts` are left out (`exclusion(of:)` names the setting, so when none is left the message lists only the settings that removed something).
- `CalendarView.swift`: rebuilt on `show` only when `renderKey` (the state, the query, and the minute while loaded) changed, with `preferredHeight` following the content (every section has a fixed height, summed as it is added). `.upcoming` gets "next up first" (`nextUpSections`): a line for the timed events under way, a `NextCard` for the first timed event still to start (countdown in minutes under an hour, else its time and day; an end on a later day names that day, there and in the "en cours" line), then two columns of `CompactRow`s (rest of today, and the next day with events, `rowsPerColumn` each) and a count of the rest; the provider passes every upcoming event and the view picks. `.search` gets the list (day headers, then one `EventRow` per event: calendar color, time, title, and "en cours" / "dans N min" or the location). `.day` gets one header (`dayTitle`: Aujourd'hui, Demain, Hier, else the date, with the year when it isn't this one) and its `EventRow`s, finished ones dimmed. Labels are French.

- `MeetingStripView.swift`: the next meeting, on the left of the strip above the input (opposite the weather): calendar color, title and when (`NextMeeting`, main actor for `CalendarView`'s formatters and checked by the self-test: `index` / `find` is the first timed event still to start, which `nextUpSections` also uses for the card; `whenText` is "dans N min" within the hour (`CalendarView.soonInterval` and `minutesUntil`, shared with `EventRow` and `NextCard`), else the clock, "demain HH:mm" or "mer. 4, HH:mm"). `LauncherController.updateMeetingStrip` runs in `prepareToShow` (after `inputDidChange`, so a prefilled `/cal <text>` takes the one fetch slot first), `calendarDidUpdate` and the 30 s timer (which, with no event list shown, refreshes only the strip without parsing the input), never per keystroke (it doesn't depend on the input); it says "Agenda…" (`showLoading`) until the first events arrive, `show` touches the tool tip only when the event changes (setting it dismisses one being read), and `holdsStripRow` keeps the line's room until the panel closes once it was up while shown, so the input never moves up under the caret. It shows it only while `Config.calendarStrip` is on and `CalendarProvider.canReadWithoutAsking` (access already granted, in a bundle, no prompt up, since the status can read granted before `accessAnswered` replaces the store: the strip never asks, since the prompt closes the panel), reading `state(for: .upcoming)`, so it shares `/cal`'s events and fetch. Clicking it (`showCalendar`) records `launcher.meetingStripClicked` and puts `/` + `calendarKeyword` in the input through `complete(with:)`, or beeps when no `cal` workflow takes it. `didHide` hides it, so a calendar update while closed never restarts the timer or fetches.

`LauncherController.updateCalendar` fills and shows it. A 30 s `calendarTimer` runs while the event list or the next meeting is shown (`updateCalendarTimer`) so countdowns follow the clock; it and `CalendarProvider.onUpdate` go through `calendarDidUpdate`, which refreshes the list, the meeting (only while the panel is shown) and the height once. `updateCalendar` and `updateWeather` each end with `updateHeight` (`inputDidChange` calls both with `resize: false`, then resizes once; `updateMeetingStrip` leaves it to its caller), which sizes the panel for the strip (`stripHeight`), the input row and the `InputArea` shown, else the suggestion list. Loading and error lines in both areas are the shared `StatusRow`. The suggestion list is empty while the event list is shown.

### Transit/

The departure board under the launcher input while it runs a workflow whose first keyword is `Config.transitKeyword` (`LauncherController.runsTransit`, from `currentCommand`, into `showsTransit`; the shipped workflow is `transit` / `metro`), and only while `Config.transitStation` (a station id of the transit service, `A32+D20`) is set. Enter runs the workflow. The trains come from the [transit](https://github.com/erakor/transit) service's `/subway/arrivals`, which decodes the MTA's GTFS-Realtime feeds and joins in names and colors; there is no protobuf or MTA code here.

- `TransitAPI.swift`: `TransitLoader.load` makes one request through `HTTPSession` (signpost `transit.load`), with the token in `X-Transit-Token` (never `Authorization`, which the service's CDN won't cache); `url(for:limit:service:)` encodes the station id's `+` as `%2B`, and `snapshot(from:fetchedAt:)` (pure) decodes the answer into a `TransitSnapshot` (`updatedAt` is the feed's time, `someLinesMissing` its `unavailableFeeds`). `TransitError` (`offline`, `token` for a 401, `server`, `badResponse`) with `message` / `usageName`. `TransitBoard.make(from:now:limit:)` (pure) sorts each direction, drops trains more than `departedAfter` (15 s) gone, and keeps `limit`; `countdown` and `age` are its texts.
- `TransitProvider.swift`: main actor. Keeps the last `TransitSnapshot` (shown for `snapshotLifetime`, 3 min, even while a new fetch fails), `refreshIfStale` fetches once it is older than `Config.transitCacheLifetime`, one at a time, failures retried after 15 s, and only while `Config.transitService()` is set (never in the `SELFTEST` build; `setSnapshotForSelfTest` stands in). Without one, `state` is a failure saying how to set it up.
- `TransitView.swift`: the `InputArea` view, fixed `height`; two `DirectionColumn`s of rows (a drawn `RouteBullet` in the service's colors, the countdown, the clock time), a footer with the data's age, `StatusRow` while loading or failed. Labels are English.

`LauncherController.updateTransit` (from `inputDidChange`, `transit.onUpdate` while shown, and a 10 s `transitTimer` that runs only while the board is shown) records `transit.shown` once per opening, calls `refreshIfStale` and redraws from the snapshot with the current time, so countdowns follow the clock without a refetch. `didHide` cancels the fetch and stops the timer. Checked by `Tests/SelfTest/TransitTests.swift` against a recorded-shape answer of the service.

### BuiltIns/

Answers the launcher works out itself, shown in the hint and copied to the clipboard by Enter (`LauncherController.copyAnswer`, which records `BuiltInKind.usageCounter`), with the kind's SF Symbol as the input icon. `BuiltIns.answer(for:workflows:context:)` returns nil unless no workflow takes the input (`workflowAwaitingArgument` nil and `CommandParser.isUnmatched`), so `/` input is never a built-in's and, with no prefix, a workflows.json keyword always wins; a built-in's input is never an app's (`inputCanNameApp`), and ⌘↩ skips built-ins. `BuiltInAnswer` is `.result(kind:hint:value:detail:)` or `.incomplete(kind:message:)` (input that is the built-in's but has no answer yet, like `= 3*`: the hint shows why and Enter beeps rather than searching). `LauncherController.currentBuiltIn` holds it, worked out once per input change in `inputDidChange` (the list, the hint and `inputCanNameApp` read it); Enter works it out again, so `now` and `uuid` copy fresh values. Everything here is nonisolated and pure given a `BuiltInContext` (now, time zone, locale, UUID maker; `.current` in the app).

- `BuiltIns.swift`: dispatch on `Config.calculatorPrefix` (`=`), `timeKeyword`, `uuidKeyword` (alone only) and `timestampKeyword` (`now`, `now utc|unix|ms|date`, anything else after it is not taken). `separators` and `splitOnLastSeparator` (case-insensitive, last one wins) serve both units and time zones. A conversion is tried before the "type the unit" hint, so `= 30 cm in in` converts.
- `Calculator.swift`: recursive-descent evaluator over `Double` (`+ - * / ^ **`, unary minus binding looser than `^`, postfix `%`, implicit multiplication, `.` or `,` decimals, exponents, a few one-argument functions and constants); `CalculatorError` carries the hint's message. A comma that could group thousands (1 to 3 digits, not `0`, then `,` and exactly 3 digits) is `ambiguousComma`, and recursion past `Parser.maxDepth` (counted in `parseUnary` and `parsePrimary`) is `tooDeep`, so pasted input can't overflow the main thread's stack. `format` prints whole numbers plainly, else `%.12g`.
- `UnitConverter.swift`: its own unit table (factor and offset to a base unit per `Quantity`; names are lowercase except `exactUnits`, matched as typed first, where `Mb`-style names are bits), `<amount> <unit> in|to|en|->|→ <unit>` split on the last separator, the unit taken as the longest known name ending the left side that doesn't follow a letter, the amount evaluated by `Calculator`. nil when the text isn't shaped like a conversion, so it is a plain calculation.
- `DateMath.swift`: an extension of `DateMath`, whose date reading (`parseDate`, `YearlessDate`, `days(from:to:calendar:)`) and `BuiltInContext` are in `Shared/DateReading.swift`, also used by the calendar. `days [until|since] <date>`, `days from <date> to <date>`, `week [<date>|<n> [<year>]]`, and date arithmetic, which `calculate` tries before the converter (`DateMath.calculate`: `<date> ± <n> <unit>…` or `<date> - <date>`). Dates are day first (`25/12`), ISO, with an English or French month name, or a word (`today`, `demain`, weekdays); `YearlessDate` says which year a date without one means. It returns nil, leaving the input to the calculator, unless a duration or a word date is part of it, so `= 25/12` stays a division. Weeks are ISO 8601 (`Calendar(identifier: .iso8601)` in the context's zone), and day counts go from start of day to start of day, so daylight saving never shifts them.
- `WorldClock.swift`: `time [<clock>] [<place>] [in <place>]`. Places: `utc±h[:mm]` (read before `normalize`, which turns `-` into a space), here / utc, a table of extra cities, French names and island zones, the system zones by identifier and, outside the Antarctica / Arctic / Atlantic / Indian / Pacific regions (whose cities are often plain words), by city (Etc/ left out, their signs are reversed), then a short `abbreviations` list (not `TimeZone.abbreviationDictionary`, whose CAT or ART are words). Input naming no place returns nil, so `time machine` or `time christmas` goes to apps and the search. The hint uses the locale's format; the copied value is always `HH:mm` (en_US_POSIX).

### Shared/Signposts.swift

`Signposts.signposter` is one `OSSignposter` (subsystem: the bundle ID or `local.launcher`; category `performance`) used for intervals around the work that could cost a frame: clipboard store load/save, poll, image save, panel open/reload/filter/preview, thumbnail decodes, restore write, launcher `inputDidChange`, `AppIndex.results`/`scan`, `SettingsPanes.installed` (`panes.scan`), calendar fetch, the `/stats` report, weather, transit and preview loads, `StoreFile` load/save (the full list is in the root README's "Measuring performance"). Metadata is counts, sizes and kinds only, never text, queries, paths, URLs or bundle IDs (a search field's text is reduced to its length): numbers are interpolated with `privacy: .public`, and kinds are `Signposts.Kind` cases, whose names (a fixed list) are the only public strings, logged by `Signposts.end(_:_:_:)` (an `OSLogMessage` can't be passed through a wrapper, so a message with numbers calls the signposter directly; values in it need an explicit `self.`). The plain self-test binary logs as `local.launcher.selftest`, like the test bundle. Intervals that can overlap (background or async) use `makeSignpostID()`; main-thread ones use the default exclusive ID. `Tests/signposts.sh` prints them live with durations, without Xcode.

### Shared/StoreFile.swift

`StoreFile` (main actor) is a versioned JSON data file, used by `UsageStats` (usage.json) and `TypedAppPicks` (typed-picks.json); the owner keeps the contents and passes a closure returning them to each `scheduleSave` (held, with its owner, only until that save, like a timer's target). `load(_:currentVersion:)` reads the `version` field first: missing file → nil; newer → nil with `canSave` off for the run, file left in place; older, or anything that doesn't decode → `SetAsideFile.move` (`canSave` off if that fails). `scheduleSave` writes 5 s later (a block `Timer` in `.common` mode), `saveNow` writes a pending change at once (on quit), always into a 0700 folder as an atomic 0600 file, with `store.load` / `store.save` signposts (`kind=` the file, `bytes=`). The stored structs are plain `Codable` with a `version` field. `DayKey` (same file) is the shared `yyyy-MM-dd` local day key and the "last N calendar days" cutoff, counted in calendar days so daylight saving doesn't shift it. ClipboardStore keeps its own save path (it also excludes from backup and manages image files).

### Shared/HTTPSession.swift

`HTTPSession.shared` is an ephemeral `URLSession` used by `WeatherLoader`, `TransitLoader` and `PreviewLoader` instead of `URLSession.shared`: the WeatherAPI key is in the request URL, so it has no URL cache and no cookie storage at all (not even ephemeral's in-memory ones). Its delegate (`HTTPSRedirectsOnly`) follows a redirect only to https, and only on the same origin for a request carrying one of `credentialHeaders` (the transit token: URLSession copies headers across redirects), through `allowsRedirect`; a refused one ends the request with the 3xx response, which callers treat as a failure. `removeLegacyCache`, at launch, empties `URLCache.shared`, which earlier builds filled with weather URLs holding the key.

### Shared/ShortcutModifiers.swift

`NSEvent.shortcutModifiers` is the event's ⌘ ⌃ ⌥ ⇧ only. Every ⌘-shortcut check (`LauncherPanel`'s editing shortcuts, both `handleKeyEquivalent`s) compares it to `.command`, so Caps Lock, keypad Enter and fn never break a shortcut. Use it for new shortcuts too.

### Shared/HotKeys.swift

Carbon `RegisterEventHotKey`, deliberately avoiding Accessibility/Input Monitoring permissions. Don't switch to `NSEvent` global monitors or CGEventTap. macOS 15+ rejects Option-only hotkeys.

### Shared/UsageStats.swift

`UsageStats.shared` (main actor) keeps local counters in `~/Library/Application Support/Launcher/usage.json`: daily buckets keyed `yyyy-MM-dd` (local time), each a set of name → count maps (`counts`, `keywords`, `fallbackWords`, `clipboardCopies`, `clipboardRestores`, `appsOpened`), keeping the last `Config.usageRetentionDays` calendar days, today included (cutoffs from `firstDayKey(keeping:)`, i.e. `DayKey.first`), read and saved through `StoreFile` (an unreadable file set aside, a newer `version` left in place with saving off for that run, saved 5 s after a change and on quit, 0600). Simple counters are `UsageCounter` cases (the raw value is the name in the file); weather failures are `weather.failed.<WeatherError.usageName>`. Workflow runs are keyed by `keywordKey(_:withArgument:)` (`pr`, `pr …`; `keyword(fromKey:)` reads one back), the one place the format lives for the ranking, the cards and `/stats`. Hooks: `PomodoroTimer`'s `focusSessionFinished` (an init parameter, set by the app's convenience init, a no-op in tests: `pomodoro.focusCompleted` through `record(_:on:)`, on the day the session ended, restored ones included; a day before the kept ones is dropped, a later one counts today), `LauncherController` (opened, closed without launching, Enter needing an argument, a command card clicked, the weather strip or the next meeting clicked, `recordAppOpened` by bundle ID, `recordLaunch` with `Command.source`, a built-in's answer copied by kind), `PreviewFetcher` and `WeatherProvider` (loaded / failed, cancellations not counted), `LauncherController.updateCalendar` (`calendar.shown`, once per opening), `ClipboardStore.add` (copy by kind and bundle ID), `ClipboardMonitor` (skipped: marked, ignored app, text, image), `ClipboardController.pickSelected` (restore per bundle ID, restore failed). The menu bar's "Usage…" shows `summary(days: summaryDays)` in an alert, and `/stats` (`Sources/Stats/`) reads `merged(days:)` (a `UsageDay` of the last N days, added up with `UsageDay.add`), `totals()` and `countingSince(withinLast:)` (the first day with counters when later than the first of the last N days, today with none, nil when they reach back over all of them). `totals()` (apps opened and keywords run over every kept day, empty when tracking is off) also ranks the launcher list, so it is read data, not just a report: renaming a key in the file changes the ranking. Never record content: no arguments, queries, clipboard text or file paths. The one exception is the first word of a multi-word fallback input (or of an unknown `/` command, `recordUnknownCommand`), only when it is a workflow keyword or a typo away from one (`fallbackWord(in:keywords:)`, optimal string alignment distance 0 for keywords of 1 to 3 letters, 1 for 4, 2 for 5+; `LauncherController` passes `WorkflowSet.keywords`), behind `Config.usageTrackFallbackWords`. Every record call is a no-op when `Config.usageTracking` is false.

### Shared/FloatingPanel.swift

`LauncherPanel` is a borderless non-activating `NSPanel`, so the previously frontmost app stays frontmost. `FloatingPanelController` is the shared base for both panels: frosted background, positioning on the screen under the mouse, fade in/out, dismissal on Esc / click-away / hotkey. `setHeight(_:)` grows or shrinks a panel downward, keeping its top edge where a panel of the original size would sit. Subclasses override hooks (`prepareToShow`, `didHide`, `initialFirstResponder`, `didFocus`, and `handleKeyEquivalent`, which sees ⌘ shortcuts before the panel's standard editing ones) and add views to `contentView`; it also provides shared view factories like `makeHintLabel()`.

### Launcher/LauncherController.swift

`LauncherController` (a `FloatingPanelController`) runs the launcher: the input field, the hint line, the suggestion list, and Enter handling. The area under the input is the suggestion list or one `InputArea` (`inputAreas`: the command cards, the forecast, the event list, the pomodoro view and the usage report), each a view, its height, a `claims()` test on the input as it reads now, and optionally its own `hint` (what Enter does there, shown by `updateHint` in place of the command's title; the pomodoro's). That list is the one place that lays them out, hides them in `didHide`, empties the suggestion list while one claims the input (`updateSuggestions`) and sizes the panel for the one shown (`updateHeight`, which also keeps its height constraint); the feature fills its view and sets `isHidden`. Enter does nothing when a keyword that needs an argument is typed alone. When an `AppIndex` scan finishes, `appsDidChange` refreshes the list only while the panel is shown, and keeps the highlighted row (`SuggestionListView.select`, matched with `LauncherItem.isSame`) so Enter still does what was shown. When `matchedResult()` finds an app or a System Settings pane and no suggestion row is chosen, the search icon shows the app's icon (System Settings' for a pane), the hint reads `↩ Open <name>  ⌘↩ <fallback title>`, Enter opens it, and ⌘↩ (`handleKeyEquivalent`) runs the fallback search instead. A command whose URL has the `alfresco` scheme is not opened: it goes to the `internalURLHandler` closure from `AppDelegate`, and a `false` result beeps and keeps the bar open. That's how workflows.json reaches in-app features without a schema change.

### Launcher/SuggestionListView.swift

`SuggestionListView` is the list under the input, Alfred-style rows (icon, title, subtitle, and `↩` on the highlighted row or `⌘N` on the first nine). Its rows are `LauncherItem`s: `.app(AppEntry)`, `.settingsPane(SettingsPane)` (System Settings' icon, its name as subtitle) and `.workflow(Suggestion)`. `LauncherController.updateSuggestions` fills it with the best matching app or pane first (highlighted from the start, since Enter opens it anyway; ↑ stops there), then `WorkflowSet.suggestions(for:)` (workflows whose keyword starts with the single word typed after `/`; empty once the word is every match's whole keyword; every workflow for `/` or `/help`) reordered by `sortedByUse` (the fully typed keyword first, then most run), then the other `AppIndex.results`. Both rankings use the `UsageTotals` read in `prepareToShow`, so Enter and the first row always agree. Up to nine rows unless there are more keywords. Workflow icons are the icon of the app that opens the URL (`WorkflowIcon`, in `WorkflowCardsView.swift`, shared with the cards), cached per scheme until the list empties. The input keeps focus, so `LauncherController` routes Tab (completes `tabTarget`: the highlighted row, else the first; `LauncherItem.completion` is an app's or pane's name or `Suggestion.completion`, the keyword with its prefix plus a space when the workflow takes an argument), ↑ ↓ (only while the list has rows), and Enter, a click or ⌘1 to ⌘9 (`activate`: an app or a pane opens; a workflow is completed, then run if it takes no argument). With no row highlighted, Enter is unchanged. Moving the mouse over the list highlights the row under it (`mouseMoved` from one tracking area on the list, moves only, no enter / exit, so rows replaced or scrolled under a resting pointer never pick one), as ↓ would, so Enter takes it; `onHover` updates the hint, and leaving the list keeps the highlight. The list sits where the forecast and the calendar list go and is empty while an `InputArea` claims the input; its height is part of `updateHeight`.

### Launcher/WorkflowCardsView.swift

The command cards: an `InputArea` shown while the input is empty or only spaces (`LauncherController.showsCards`, also off with `Config.workflowCardLimit` nil or no workflows). `WorkflowCard.cards(from:usage:limit:)` (nonisolated, pure) makes one card per distinct first keyword in file order, joining its bare and `{query}` forms (`WorkflowSet.workflow(for:withArgument:)`; title, help and icon from the bare form when there is one), counts its runs as `UsageStats.recordLaunch` keys them (`kw` for the bare form's first keyword plus `kw …` for the argument form's), sorts by runs with file order on ties, and keeps `limit`. The usage is `LauncherController.usage`, read in `prepareToShow`. `WorkflowCardsView` lays them out by hand, three per row (`columns`), and rebuilds only when a card's text changed (`renderKey`); `preferredHeight` follows the rows. A card is never first responder, so a click (on mouse up, inside) leaves the input focused: `LauncherController.pick` records `launcher.cardPicked` and calls `complete(with:)` with `WorkflowCard.completion` (`/kw`, plus a space when a form takes an argument; the input is trimmed, so `/kw ` still runs the bare form), which makes the input non-empty and so hides the cards. Nothing runs on the click.

### Pomodoro/

The pomodoro timer. No hotkey or panel: it's controlled through `alfresco://pomodoro/<action>` URLs (the `/pomo` workflows in `workflows.json`) and shown in the menu bar and, while the input runs one of those URLs, under the launcher input.

- `PomodoroTimer.swift`: main actor. `PomodoroState` is `.idle`, `.running(phase, endsAt:)` or `.paused(phase, remaining:)`; `PomodoroPhase` is focus / short break / long break. Time left is always computed from `endsAt`, and a 1 s `Timer` in the `.common` run loop mode runs only while running. `NSWorkspace.didWakeNotification` runs a tick right away, so a phase that ended during sleep alerts on wake; one that ended more than `lateWakeLimit` ago (the length of the following break) ends quietly into a paused next phase, like `restore()`. A focus session leads to a break (long after `Config.pomodoroSessionsBeforeLongBreak`), and a break leads to idle. `skip` advances without the alert; `stop` resets the cycle. Every change is saved to `pomodoro.json` in `ClipboardStore.directory` and restored at launch; a phase that ran out meanwhile advances quietly into a paused next phase. Observers added with `addObserver` (the status item, through `connect(to:)`, and `LauncherController`) run on each change and tick, `onPhaseEnd` when a phase runs out by itself; `connect(to:)` also wires that to `PomodoroAlert`. `focusSessionsToday` counts focus sessions that ran their full length (`finish`'s `ranOutAt`, nil on skip), on the local day of their end date rather than the day they were noticed (wake, restore); it is saved as `lastFocusEnd` and `focusSessionsOnLastDay` in `pomodoro.json` (absent in older files, read as none) and `stop` keeps it.
- `PomodoroCommand.swift`: parses the URL path (`toggle`, `start`, `pause`, `resume`, `skip`, `stop`, or 1 to 180 minutes); nil makes the launcher beep. `AppDelegate.handleInternalURL` asks for the notification permission when it starts a session and runs it with `PomodoroTimer.run(_:)`, false (beep) where the timer's guards refuse it. `PomodoroCommand.preview(of:state:completedFocusSessions:now:)` (pure) says what it would do now, with `runs` matching `run`'s result (the self-test compares the two in every state); `startMinutes` is the focus length it would start.
- `PomodoroView.swift`: the `InputArea` under the launcher input (`LauncherController.pomodoroURL`: the input parses to a command whose URL's `InternalURL.feature` is `pomodoro`, and the launcher was given a timer; `LauncherController(store:pomodoro:internalURLHandler:)`, nil in tests that don't need it), parsed once per input change into `currentPomodoroURL`, which its `claims` reads. `PomodoroViewContent` (no AppKit, checked by the self-test) holds its texts: a card with the phase, the clock (the length `/pomo [minutes]` would start while idle), the end time or "Paused" and what follows, then the cycle and `focusSessionsToday`; fixed height; the idle cycle count comes from `PomodoroTimer.cycleCountAtStart`, the rule `startFocus` uses, and icons and minutes from `PomodoroPhase.symbolName` / `.minutes`, shared with the status item and the alert. While it is shown, the hint is the area's own (`PomodoroTimer.preview(of:)`, which passes the timer's clock so a phase that ran out but hasn't ticked reads "End the …", what `pause` then does), and `LauncherController.pomodoroDidChange` (a timer observer) refreshes both on every tick while the panel is shown, without parsing the input again. Labels are English, like the menu bar item.
- `PomodoroStatusItem.swift`: its own `NSStatusItem`, independent of `Config.showMenuBarIcon`, created while the timer isn't idle and removed when it is. Its `NSMenu` is built once and reused, since a menu item can only be in one menu.
- `PomodoroAlert.swift`: through `PomodoroAlert.sink` (`SystemPomodoroAlertSink`: `NSSound` and `UNUserNotificationCenter`; the self-test swaps in a recorder), plays `Config.pomodoroSound`, and posts a `UNUserNotificationCenter` notification only when `Bundle.main.bundleIdentifier` is set (`UNUserNotificationCenter.current()` raises in the plain binary). The notification calls are kept out of main-actor code because their completion handlers run on a background queue.

### System/

`SystemCommand.swift`: `alfresco://system/<action>` (`sleep`, `lock`, `displaysleep`; the workflows `zz`, `lockscreen` and `displaysleep` in `workflows.json`, typed after `/`, and kept away from everyday words since `UsageStats.fallbackWord` records words a typo away from a keyword), run by `AppDelegate.handleInternalURL`, which switches on `InternalURL.feature(of:)` (the URL's host; `Shared/InternalURL.swift`, whose `action(of:feature:)` both `SystemCommand` and `PomodoroCommand` parse). A new `alfresco://` feature is a `feature` constant, a command type and a case in that switch. Sleep and display sleep run `/usr/bin/pmset sleepnow` / `displaysleepnow` after `SystemCommand.delay` (0.5 s, so releasing Enter doesn't wake the Mac); a pmset that then fails to start or exits non-zero beeps from its termination handler, since the launcher has already closed. Lock calls `SACLockScreenImmediate`, resolved with `dlopen`/`dlsym` from the private `login` framework, and returns false (beep) if it is missing or returns non-zero. None needs a permission; don't switch lock to posting ⌃⌘Q, which would need Accessibility. The self-test checks the parsing and that the symbol resolves, never runs them.

### Stats/

`/stats`: the usage report under the launcher input. `stats` is a workflow in `workflows.json` pointing at `alfresco://stats` (`StatsCommand.feature`; `isSummary` is the bare URL, the only action). `LauncherController.runsStats` (from `currentCommand`, the input parsed once per change and shared with the calendar and pomodoro areas, into `showsStats`; false while `Config.usageTracking` is off) claims the area, whose own hint is `↩ Last <UsageStats.summaryDays> days in detail`; Enter goes through `AppDelegate.handleStatsURL`, which opens the menu bar's Usage… alert in a `Task` so the launcher closes first.

- `UsageReport.swift`: `Equatable`, `Sendable`, no AppKit (checked by `Tests/SelfTest/StatsTests.swift`). `init(recent:kept:days:countingSince:unusedSince:workflows:appName:)` makes the four figures (`commandsRun`, both forms of every keyword; `appsOpened`, the `launcher.openedApp` counter; `clipsRestored`; `focusSessions`), `topCommands` (both forms on one line, `keyword(fromUsageKey:)`) and `topApps` (by `appName`, `unknown` left out), at most `listLimit` each, and `unusedCommands`: `WorkflowCard.cards` with no limit whose `runs` over `kept` (every kept day) is 0, in file order, leaving out workflows that open the report (`opensReport`). `make(from:workflows:days:appName:)` (main actor) fills it from a `UsageStats`; the self-test passes its own `appName`. `title` and `unusedLine` are its texts. Labels are English, like the Usage… alert.
- `StatsView.swift`: the `InputArea` view, fixed `height`; `show` rebuilds only when the report changed. `LauncherController.updateStats` makes the report only when the view appears (signpost `stats.report`), not on later keystrokes. Figures are `NSBox` tiles and the bars are drawn in `draw(_:)`, so both follow light and dark mode. Command icons come from `WorkflowIcon`, app icons from the bundle ID, cached in the view.

### App/Launcher.swift

`AppDelegate` runs as an accessory app, registers both hotkeys, owns the clipboard store/monitor and the pomodoro timer, routes `alfresco://` URLs (`handleInternalURL`, a switch on the host), and builds the optional status-bar menu (its "Start Pomodoro" item is disabled through `validateMenuItem` while a session runs; "Launch at Login", `LoginItem.swift`, is `SMAppService.mainApp` on macOS 13+: `validateMenuItem` shows `LoginItem.state` (`.requiresApproval`, also what turning it off in System Settings gives, is a dash and a click opens Login Items) and enables it only for a bundle directly in `/Applications` or `~/Applications`). Alerts go through `NSAlert.runModalInFront` (`App/Alerts.swift`), which activates the accessory app first. `install.sh` finds running copies by who holds `launcher.lock` (`lsof`; the path comes from the new build's `Launcher --lock-path`, `LauncherApp.lockFileURL`, handled before the lock like `--check`), stages the new bundle beside the old one and swaps it in only once every copy has quit. The Workflows submenu is rebuilt in `menuNeedsUpdate`. `LauncherApp.main` first sets `umask(0o077)`, so everything the app writes is owner-only from creation (an atomic write's temporary file included), then takes an exclusive `flock` on `~/Library/Application Support/Launcher/launcher.lock`; a second copy (plain binary, `build/`, or the installed app) exits with status 0 instead of fighting over the hotkeys and clipboard history.

### Clipboard/ClipboardHistory.swift

- `ClipContent` is the model and the extension point for new kinds: `.text`, `.image(ClipImage)` and `.files([String])` (absolute paths; references only, the files aren't copied). Its on-disk encoding tags each item with a `"kind"` so older builds skip unknown kinds. `ClipItem` records the source app's name and bundle ID (for its icon), and `pinned` (decoded with `decodeIfPresent`, so older files read as unpinned).
- `ClipboardStore` keeps the history with pinned items first (latest pin on top; `load` restores that order, `pinnedCount` counts them), then the rest newest-first, prunes unpinned items older than the retention window on a timer, saves to `~/Library/Application Support/Launcher/clipboard-history.json` with a debounced save, and calls `onChange` so an open panel can refresh. Image data lives outside the JSON as `clipboard-images/<sha256>.png` (`ClipImage.hash` and the pixel size are validated on decode, because the hash becomes a file name and the size gets multiplied). Another running copy of the app shares that folder, so a save deletes only image files this process referenced and stopped using (`knownImageFiles`); at launch, unused files older than the retention window are swept, which is safe because copying or promoting an image refreshes its file's modification date. Load drops image items whose file is missing, and an unreadable history file is set aside with `SetAsideFile.move` (`canSave` off if that fails) rather than overwritten; the set-aside file's date is refreshed, and `removeStaleSetAsideFiles` (at launch and on each prune tick) deletes `clipboard-history.unreadable*.json` once older than the retention window. `excludeFromBackup` marks the history file (after every atomic save, which drops the flag) and `clipboard-images/` as excluded from backups, so new Time Machine backups don't include the history; earlier backups and snapshots keep what they have. The rest of the support folder (usage, pomodoro) is still backed up. `add` places items by `copiedAt` among the unpinned ones, since images arrive late; copying a pinned item's content again only updates its `copiedAt`, and `clipboardMaxItems` counts unpinned items only. `setPinned(id:_:)` moves a pinned item to the top, or an unpinned one to the top of the rest with a fresh `copiedAt`, and returns false past `clipboardMaxPinnedItems` (or `clipboardMaxPinnedImages` for an image); `promote` leaves a pinned item in place; `clear` keeps pinned items. Pinned image files are touched at launch, since they can outlive the retention window that `removeStaleImages` relies on.
- `ClipboardMonitor` polls `NSPasteboard.changeCount` (macOS has no clipboard change notification). One copy is recorded as one kind: file URLs, then text, then an image of a type `ClipImageFile.save` can convert (`imageTypes`: the `NSImage.imageTypes` ImageIO reads, plus PDF), except that an image wins over file URLs that all point to temp/cache locations and over text that is only an http(s) link. `recordImage` reads the bytes and checks the pixel size from the header on the main thread; `ClipImageFile.save` (PNG conversion, hashing, writing; not main-actor) runs in a detached task. It skips items carrying the nspasteboard.org `Concealed` / `Transient` / `AutoGenerated` markers or the older app-specific ones (`ignoredTypes`), copies made while an app of `Config.clipboardIgnoredApps` is frontmost, oversized or whitespace-only text (`isRecordable`: the size is checked first and no trimmed copy is made, since copied text can be huge), oversized images, and whatever was on the clipboard at launch. After reading, `poll` (and `recordImage`) drop the copy if `changeCount` moved since the markers were checked, so a newer copy is never recorded unchecked; the next poll handles it. `ClipImageFile.save` checks the header's pixel size itself; data ImageIO can't read is taken as a PDF (`pdfPNGData`: page 1 drawn with CoreGraphics into a bitmap of one pixel per point, its size checked before drawing, never `NSImage`, whose rendering follows the screen's scale). `ClipboardStore.init(directory:)` (the self-test passes its own folder) makes its folder and `clipboard-images/` 0700 once (`ClipImageFile.makePrivate`, non-fatal), for folders an earlier build created; `createPrivateDirectory` only sets that mode on a folder it creates. `Config.clipboardIgnoredApps` is best effort: it is the app in front at the next poll, not the app that copied. The monitor takes its `NSPasteboard` in `init` (`.general`; the self-test uses a private named one).

### Clipboard/ClipboardPanel.swift

`ClipboardController` (a `FloatingPanelController`) shows the history: search field + `NSTableView` (left) filtered by `ClipFilter` (`ClipFilter.swift`), and `ClipPreviewView` (right) showing the selected item in full. `ClipFilter` folds each item's `ClipContent.searchTexts` and the query with `AppIndex.fold` and matches whole characters (`ClipFilter.contains`: a literal search whose match must start and end on character boundaries), keeping the folded texts per item ID across openings (an item's content never changes) until `historyDidChange(items)`, called from `store.onChange`, drops those of items gone from the history; a query that contains the previous one only looks through the previous matches, and `historyDidChange` makes the next search look through everything again. Row icons are the source app's icon (text), a thumbnail (images) or the Finder icon (files). Thumbnails and preview pictures come from `ThumbnailLoader` (`ThumbnailLoader.swift`), which decodes with ImageIO in a detached task, one file at a time, newest request first, caches the result costed by size and hands the picture (or nil for a file it can't decode) to `onLoad`; the panel puts it straight into the visible cell or the preview (`ClipPreviewView.setPicture`) rather than reloading, since `NSCache` may already have evicted it. Never decode an image on the main thread here: a PNG has no embedded thumbnail, so it is decoded in full. Row thumbnails (`rowThumbnails`) are kept across openings, since `clipboard-images` files are named by content hash, but only for images still in the history: `store.onChange` calls `keepOnly` with their paths (and `previews.keepOnly` with those and the copied files' paths), which drops the pictures, failures and waiting requests of the others (and the result of a decode running for one), so a cleared, deleted or expired image's thumbnail doesn't stay in memory; its waiting requests are dropped (`cancelPending`) when the table reloads and when the panel hides, and its failures are forgotten on hide so the next opening retries them. Previews (`previews`, also used for copied image files; an image clip that can't be decoded shows a "photo" symbol) and the app and file icons in `imageCache` are emptied when the panel hides. The three caches share 128 MB (32 icons, 16 thumbnails, 80 previews). Picking an item (↩, a click on a row, or ⌘1 to ⌘9 for the first nine rows, matched by key code so other keyboard layouts work) writes it back to the clipboard, moves it to the top, and pastes it: `didHide` calls `PasteKeystroke.post()` (`PasteKeystroke.swift`), which posts ⌘V with `CGEvent` once the panel is gone, using the key that types "v" in the current layout. That needs the Accessibility permission (the hotkeys still don't); without it the first pick of a launch shows the system prompt and the item is only copied. ⌘↩ (or ⌘-click) copies without pasting. With no query, the panel opens on the first unpinned row (`reload`), so ↩ still pastes the latest copy. ⌘P (`togglePinSelected`, matched by character in a Latin layout, else by `kVK_ANSI_P`) pins or unpins the selected item, records `clipboard.pinned` / `clipboard.unpinned`, and beeps past the limit; pinned rows show a `pin.fill` symbol, and the hint says "pin" or "unpin" for the selection. Restoring beeps and leaves the clipboard alone if the image file or every referenced file is gone. ⌘S (`startNaming`, matched like ⌘P) names the selected item as a snippet: `namingID` turns the search field into the name's field (the list keeps the earlier search through `currentQuery` and doesn't reload as you type; ↩ `saveName`, esc `endNaming`, ↑ ↓ ignored, ⌘ shortcuts left to the field), and a name `ClipboardStore.setSnippetName` refuses beeps and keeps naming. A delayed ⌘V goes through `PasteKeystroke.target()` (nil without Accessibility, which it then asks for) and `PasteKeystroke.paste(into:)` (50 ms later, skipped if the front app, the change count or an open panel changed).

### Clipboard/Snippets.swift, SnippetsView.swift

A pinned item with `ClipItem.snippetName` (decoded with `decodeIfPresent`; `SnippetName.normalize`: trimmed, lowercased, 1 to 32 characters, no whitespace, `/`, `?`, `#` or `%`, a bad one dropped on decode, and only on pinned items; `load` keeps the first of a duplicated name) is a snippet. `ClipboardStore.setSnippetName(id:_:)` pins the item first (false past the pin limits), takes the name from any other item, and a blank name removes it; `setPinned(false)` drops it. `ClipFilter` matches names too, outside its cache since they can change. The `/snip` workflow points at `alfresco://snippet/{query}` (`SnippetCommand.feature`; `name(of:)` is the action, `isSnippetTemplate` recognizes the workflow for `/snip` alone); `AppDelegate.handleSnippetURL` calls `ClipboardController.pasteSnippet(named:closing:)`, which resolves it (`SnippetSearch.resolved`: the exact name, else the only one starting with it), restores it like a pick (`restore`, shared with `pickSelected`; plus `clipboard.snippetPasted`), and pastes through `FloatingPanelController.runAfterHide` (run once after the next `finishHide`, dropped by `show`), so ⌘V reaches the app once the launcher is gone; false beeps. In the launcher, `currentSnippetSearch` (a `SnippetSearch` over the typed name from `snippetQuery(for:command:)`, worked out once per input change and read by the list and the hint; "" for `/snip` alone through `workflowAwaitingArgument`; it looks only through the pinned items at the head of the history) claims the `SnippetsView` `InputArea`, filled from `SnippetsViewContent` (pure: at most `maxRows` matches described by `ClipContent.summary` and `symbolName`, shared with the history's rows, the one Enter pastes highlighted, a footer for the rest or why there is none) over the `snippets` closure `LauncherController.init` takes (the store's items in the app, `{ [] }` by default); its hint is `SnippetSearch.hint`, except for `/snip` alone, where the workflow's help comes first. Checked by `Tests/SelfTest/SnippetTests.swift`.

## Conventions

- New top-level features (anything with its own hotkey or panel) get a folder under `Sources/` with its own `README.md`, linked from the Features table in the root `README.md`; additions to an existing feature stay in its folder. A user-visible change to a feature updates that folder's `README.md`. Code used by more than one feature goes in `Sources/Shared/` rather than being copied. A folder can hold a single file.
- When changing the `workflows.json` schema, update the decoding in `Workflow`/`WorkflowSet`, the field table in `Sources/Launcher/README.md`, and `Config.defaultWorkflowsJSON` if relevant. Decoding errors are turned into short user-facing messages by `WorkflowStore.describe`.
- New panels should subclass `FloatingPanelController` rather than duplicating panel setup.
- A new view under the launcher input (in place of the suggestion list) is an `InputArea` entry in `LauncherController.inputAreas`, not another case in `updateSuggestions`, `updateHeight` or `didHide`.
- Adding a clip kind means a new `ClipContent` case plus handling in `ClipboardMonitor` (read), `ClipboardController` (display and restore) and `UsageStats.recordClipboardCopy` (a `UsageCounter` for it).
- A new built-in is a branch in `BuiltIns.answer(for:context:)` returning a `BuiltInAnswer` of a new `BuiltInKind` (with its `UsageCounter` and symbol), its keyword in `Config`, checks in `Tests/SelfTest/BuiltInTests.swift` against a pinned `BuiltInContext`, and a row in `Sources/BuiltIns/README.md`.
- Work that can take more than a frame (file I/O, decoding, a loop over the whole history, a network request) gets a `Signposts` interval, with only numbers and kinds as metadata.
- New usage counters are `UsageCounter` cases recorded through `UsageStats.shared`; anything that would store what the user typed or copied needs its own `Config` switch (and, like `TypedAppPicks`, its own file).
